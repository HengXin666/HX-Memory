# Agent Note: 设置热更新 + 面板自刷新 + 文档同步门禁与技能库

Status: implemented

## Problem

三件互相关联的可靠性缺口, 都来自"只做了一次就假设永远有效":

1. **设置必须重启才生效**。用户在 DSH 设置面板改 `captureEpisodes`/`episodeRetentionDays`/`autoEvolve` 之后当轮不生效, 只有重启插件才行 —— 因为这三项在**插件构造时被读了一次**并固化进对象 (EpisodeStore 的 retention、facade 的 autoEvolve、runtime 的 episodes 实例)。设置源本身是实时的 (`settingsSource.read()` 每次都求值), 但消费者把快照存下来了。
2. **面板显示陈旧**。两个设置页 (审阅/绑定) 只在**挂载时**拉一次数据; 记忆在会话里持续产生、绑定可能被 CLI 或另一个窗口改动, 于是面板长期显示旧状态, 用户唯一的办法是重启宿主。
3. **文档与技能缺少同步机制**。文档里引用的路径在重命名/移动/删除后**静默失效**而无人发现; 也没有沉淀"怎么验证宿主接线"的可复用流程。

## Decision

### 1. 设置一律走"实时求值", 不存快照

- `RuntimeOptions.episodes` 从"实例"改成**提供者函数** `() => EpisodeStore | null`: 每次落盘时重新求值, 开关与保留期都是当前值。
- `FacadeOptions.autoEvolve` 接受 `boolean | (() => boolean)`: 传函数时每轮裁决重新读设置。
- 保留期变化时重建 EpisodeStore (它的 retention 只在构造时读)。
- 判据: **任何从设置派生的行为, 都不允许在构造时求值后长期持有**。

### 2. 面板三重自刷新

审阅页与绑定页统一: `window focus` + `document visibilitychange` + 可见时 5s 轮询 (切到后台即停, 不浪费请求)。
绑定页额外带**脏标记**: 用户有未保存编辑时跳过自动刷新, 否则会覆盖正在输入的内容。

### 3. 文档同步门禁 `scripts/verify-docs.ts` (学习 DSH 的 doc-sync, 裁剪到轻量版)

只保留最有效的两条, 挂在 `scripts/verify.sh` 与 CI 上:

- **引用可达性**: 文档里的仓库内路径必须存在。解析顺序刻意宽松 (文档所在目录 → 仓库根 → `src/` → 纯文件名索引), 避免把"提到文件名"误判成坏引用。
- **结构合规**: `docs/` 下每份文档声明"目的 / 边界 / 与代码的关系"; 无 TODO/FIXME **标记形状**残留 (散文里讨论"不留 TODO"不算 —— 旧版规则真误伤过一次)。

站外引用 (上游仓库路径、运行时数据文件) 必须用行末 `<!-- verify-docs:allow (原因) -->` **显式声明**。宁可让作者声明, 也不让 gate 猜。

**不做**: 字数预算 (本仓库文档小而变动频繁, 预算会变噪声)、外部 URL 校验 (网络抖动 → flaky gate)。

配套: 补 `tests/s1/architecture.test.ts` 把 `docs/architecture-v2.md` 声明的分层铁律变成可失败的断言 (kernel 不依赖存储/宿主、应用层不依赖适配层、引擎层不依赖上层、kernel 不引入 node:fs/sqlite)。此前文档承诺了这条测试但**文件并不存在** —— 正是本门禁要抓的那类失效。

### 4. 技能库 (`.agents/skills/`)

三个 skill, 把"怎么做"从对话里固化下来:

- `hx-record-session-replay`: **录制-回放**方法论 —— 录一次真实会话的事件帧, 之后离线回放做回归。适用于依赖真实宿主时序/进程边界/插件组合的行为; 明确列出本仓库五个既有录制点与三条纪律 (不联网、要能失败、帧要能读)。
- `hx-doc-sync`: 改完代码/文档后的同步清单 (gate + 人工四问 + "一个事实一个家"的归属表 + 站外引用怎么标)。
- `hx-memory-trigger`: 排查"记忆不生效"的决策表 (按 `TriggerDecision.mode` 定位是保底/意图/漂移/去重哪一环) 与调参旋钮。

## Alternatives considered

**让宿主在设置变更时重建插件**。看似最彻底, 但重启插件会丢运行态 (未冲刷的捕获缓冲), 且宿主不会为每个命名空间做这件事; 依赖"实时求值"更小也更可控。

**面板改成 WebSocket/SSE 推送**。实时性最好, 但要在宿主里额外开通道、处理重连; 而数据显示的时效要求只是"秒级"。focus + visibility + 轮询三件套零依赖且够用 (切后台自动停)。

**文档门禁直接照搬 DSH 全套 (doc-budgets / translation-pairing / doc-typecheck)**。它们的价值建立在双语配对与生成式目录上, 本仓库两者都没有; 照搬只会得到一堆需要维护的豁免项。取"引用可达 + 结构合规"这两条通用且高收益的。

**门禁用字数/行数预算代替引用检查**。预算约束的是"写多少", 而实际的痛是"写的路径已经不存在"; 后者才是有害的静默失效。

**把任务流程留在对话/README 里, 不建 skill**。对话会丢, README 会膨胀; skill 的 `description` 是可被自动检索触发的, 这正是"下次遇到同类问题能想起来"的机制。

## Consequences

设置改动即时生效、面板不再陈旧、文档引用失效会被拦下。代价: ①每次从设置派生的新能力都要想清楚"谁来实时求值", 写错会退回重启才生效; ②门禁对站外引用要求显式标注 (多写一个注释, 换来不会被误豁免); ③skill 需要随实践维护, 否则会变成过时的教条。

## Testing

- `tests/s2/settings-live.test.ts` (2 项): 构造时关闭 episode → 面板打开 → **当轮**就写; 反过来关闭 → 立即停止 (证明不是"只在启动读一次")。
- `tests/s1/docs-gate.test.ts` (2 项): 真实文档树通过 + 注入一份坏引用文档 → gate 必须失败 (证明门禁有拒绝能力, 不是装饰)。
- `tests/s1/architecture.test.ts` (5 项): 分层依赖方向 (kernel 零宿主依赖、应用层不依赖适配层、引擎层不依赖上层、kernel 可纯逻辑运行)。
- 真机: `scripts/smoke-dsh.sh` 仍全绿 (设置命名空间注册、RPC 可用)。
