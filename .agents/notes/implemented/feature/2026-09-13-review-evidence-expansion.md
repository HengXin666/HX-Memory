# Agent Note: 人审提议必须能看见依据 (covers 展开 + 草稿标记)

Status: implemented

## Problem

审阅面板的每条推广提议只显示三样东西: 抽象出来的规则文本、`覆盖 N 条实例`、置信度百分比。
人审要回答的问题是"这条规则该不该确认", 而**判断依据是被它概括的那几条原文** —— 面板恰恰不显示
它们。真实反馈: 用户对着 10 条待审提议问"我看不到它详细的内容是啥, 那我怎么知道要沉淀什么"。

两处成因, 都在链路上:

1. **投影把 covers 压成了计数**。`ReviewQueueView.covers` 是 `number`, 前端拿不到被覆盖条目的 id,
   自然取不到原文 (队列文件里的 id 是完整的, 只是没被传出来)。
2. **占位草稿与真抽象同形**。没有 AI 抽象器时, 启发式兜底产出的规则文本是
   `经验: <主题> 相关的 N 条实例已沉淀, 建议复核提炼为跨项目规则` —— 它只是"这个主题有一簇实例"
   的提示, 不含任何可确认的内容。实测队列 17 行: 6 条 confirmed 是真抽象 (如"派生索引必须可全量重建"),
   而 10 条 proposed 全是这种占位串, 却与真规则长得一样、同样带"确认为规则"按钮。
   已有的 `GeneralizationRunReport.usedLlm` 回答不了这件事 —— 它只描述**最近一次批次**, 而队列是跨批次的。

本仓库自己的原则 (`.agents/notes/implemented/feature/2026-09-11-generalization-observability.md`) 写着
"把它们显示成同一个『没沉淀』等于没解释", 但那条只落到了**批次级** (考虑/聚类/提议/跳过);
**条目级**一个字段都没有, 于是同一个问题在更关键的位置 (人做决定的那个位置) 又复发了一次。

## Decision

**把"判断依据"送到人眼前, 并让占位草稿当场自证是草稿。**

1. `ReviewQueueView.covers` 由 `number` 改为 `string[]` (`gateway-review.ts` 的 `toReviewView`)。
   视图给全量 id 而不是计数; 原实现给的是副本 (`[...covers]`), 防止展示层改数组回写队列行。
2. 新增 Remote `entriesByIds(ids)` (`gateway.ts`): 按 id 批量取条目, 走 `store.get` ——
   **与 confirm 落规则时读 covers 的同一入口**, 因此已撤回/已合并的实例同样如实返回 (带 `status`),
   不因可见性过滤而隐藏 (隐藏它会让"这条提议在说什么"再次变成猜测)。上限 100 条 + 去重 +
   忽略非字符串/空 id (面板传来的参数不可信); 单个 id 失效只跳过它, 不让整块展开失败。
3. 面板每条提议可**就地展开**: 调 `entriesByIds` 取回原文 (截断 1000 字), 结果按提议 id 缓存,
   收起再展开不重复请求。取不回来时明确报错, 不显示空白 (空白会被读成"这条没有实例")。
4. `GeneralizationProposal.drafted` (逐条): 无 AI 抽象时落 `drafted: true` 且
   `suggestedAction` 由 `confirm` 改为 `rewrite`。面板据此显示"草稿"徽章与一行警告
   ("文本只说该主题有 N 条实例, 请先改写为真正的规则再确认")。老队列行缺该字段 → 视图给 `false`
   (未知不等于草稿: 不给历史提议扣帽子)。
5. 提议行的元信息补上 `sourceRun` 与 `generatedAt` (此前后端已返回、前端没渲染)。
6. **面板对 `covers` 做归一化** (`client/review-covers.ts`, 纯逻辑可测): 新宿主给 id 数组,
   旧宿主给**计数** —— 面板两种都收, 且把"宿主比面板旧"显示成**可解释的状态**而不是异常
   ("面板比正在运行的宿主新 … 重启宿主即可, 数据没有丢失")。旧宿主上"看依据"按钮置灰并带
   tooltip; 宿主不认识 `entriesByIds` 时只提示一次, 不逐条报错。
   为什么必须有这一层 (真实故障): 插件产物与宿主进程是两份东西 —— 宿主启动时把 `dist` 读进
   内存, 而面板每次刷新页面都从磁盘重新加载。**只重建不重启**时面板会拿到旧契约, 直接
   `p.covers.slice()` 抛 `TypeError: p.covers.slice is not a function`, 用户看到的是
   "取不回被覆盖的条目", 完全指不出真正原因 (实测发生)。
7. 两条人审投影 (队列视图 / 被标注记忆) 拆到 `src/adapters/dsh/gateway-review.ts`, 与
   `gateway-observability.ts` 同一手法: gateway.ts 已贴着 400 行上限 (`verify-structure` 会拦),
   且"人审面"与"账本面"的变化原因不同。视图形状仍从 gateway 转出, 契约面不搬家。

## Alternatives considered

**服务端在 reviewQueue 里内联返回被覆盖条目的原文。** 面板一行代码都不用改, 但违反"投影保持薄"且
每次轮询 (5s) 都要为整个队列 hydrate 一遍正文; 队列里有草稿时正文完全用不上 (草稿根本没有可确认的内容)。
按需展开把成本限制在"人真的点了那一行"。

**只把 covers 计数改成"3 条: m1, m2, m3"文本。** 零接口改动, 但 id 对人没有意义 ——
用户要判断的是"这几条经验值不值得提炼成规则", 不是"它们的编号是多少"。

**用批次报告的 usedLlm 在面板上标注草稿。** 最省事, 但它是**批次级**的: 队列跨批次, 面板顶部说的
是"最近这批有没有用 AI", 而用户看的是队列里某一行。用它标注会把 AI 批次之前留下的草稿
显示成"AI 提炼", 正是要消灭的那种谎言。

**把占位草稿的确认按钮禁用。** 草稿仍有价值 (它把散落经验聚成一簇并给出实例清单), 禁用会把
"降级"误伤成"不可用"; 且用户可能想先确认再改写。正确做法是显式标注 + 保留按钮。

**面板挂载时预取全部提议的 covers 原文。** 省掉点击, 但队列长度无界 (实测已 17 行且会继续增长),
一次轮询就要读全库; 展开是按需的, 成本只与人的操作次数成正比。

**用 `covers` 计数兼容旧宿主 (把数字当"N 条但取不到")。** 这正是归一化做的事 —— 但它只解决
"不崩", 不解决"用户不知道为什么看不到依据"。旧宿主上必须把原因说出来 (宿主进程早于最近一次
构建), 否则按钮灰着会被读成功能坏了。反过来, **要求面板回退到旧契约** (即永远只发计数) 是错的:
版本不一致是**部署状态**, 处置是重启宿主, 不是把新契约降级成旧的。

## Consequences

- **破坏性契约变更**: `covers` 从 `number` 变 `string[]`。已同步 panel 视图、agent note 与
  `tests/s2/review-projection.test.ts`; 队列文件格式未变 (id 一直都在), 无迁移。
- 人审第一次能看到"这条规则是从哪几条经验推出来的", 并能区分"AI 提炼的规则"与"占位草稿"。
- 新增一个 RPC 出口 (`entriesByIds`): 面的增长是有代价的, 但它兑换的是人做决定时唯一缺的那块信息;
  方法名必须同时进 `remote-methods.ts` 与 gateway 的 `@Remote` (由 `tests/s2/remote-methods.test.ts` 钉住)。
- `gateway.ts` 从 399 行降到 350 行: 后续人审面继续长也不会再撞 400 行上限。
- **部署耦合被显式化**: 面板每次刷新都从磁盘加载, 宿主进程只在启动时加载插件 —— 因此
  "改了插件必须重启宿主"是本功能的隐含前提, 现在面板自己会说这件事 (此前只能靠用户猜)。
  这不是把 bug 变成提示, 而是把一个**必然存在**的部署事实变成用户可读的状态。
- 展开一次最多 100 条 × 1000 字, 单次响应有界; 但它是**同步** `store.get` 循环 (SQLite 行查),
  提议展开是人工触发、频率极低, 因此没有引入异步端口。

## Testing

`tests/s2/review-projection.test.ts` (14 项): covers 给 id 列表而非计数、视图是副本 (改视图不回写队列行)、
drafted 缺省 false 且 true 时如实透出、suggestedAction 透出; 被标注记忆只留坏评 > 0 且按总数倒序、
坏评明细与曝光一起给、limit 有界、content 截断 200 字; gateway `reviewQueue` 投影、`entriesByIds`
取回原文 / 跳过失效 id / 忽略非字符串与空 id / 去重; 以及 `drafted` 的**落盘回读**: 无抽象器时
`runBatch` 产出 `drafted: true` + `suggestedAction: rewrite` 并能穿过 JSONL 回读, 有抽象器时
两者都不出现。
`tests/s2/review-covers.test.ts` (7 项): 新宿主 id 数组原样可用; 旧宿主计数标记 `legacy` 且不可展开
(不抛错); 数组里的非字符串/空 id 被剔除; `null`/字符串/对象/NaN/负数退化成 0 条而不是崩溃;
`unknown remote method`/`method not implemented`/404 判定为旧宿主, 而 `database is locked` 与
`SQLITE_BUSY` **不算** (不能把别的故障误报成"重启就好")。
面板渲染由 `tsc -p tsconfig.client.json --noEmit` 与 `build:client` 覆盖。
