# Agent Note: 记忆反馈通道 — 由 agent 标注召回质量

Status: implemented

## Problem

HX-Memory 此前没有"这条召回到底有没有用"的信号。唯一的回路是在**返回时无条件计数**:
`adapters/dsh/index.ts` 的 `onInjected` → `reinforce(ids)` (注释写着"注入过的记忆必须算被用到"),
以及 `adapters/dsh/tools.ts` 的 `memory_search` 返回几条就强化那几条。

所以 `reinforcement` 度量的是"被返回过几次", 不是"有没有用"。真实库上已明显失真:

| kind | n | 平均 reinforcement |
| --- | --- | --- |
| rule | 6 | **24.0** |
| lesson | 8 | **0.1** |

6 条规则全是 `24` 且 `lastHitAt` 完全相同 —— 它们只是被 always-on 每轮无脑注入。

**但它精确度量了"曝光次数"** (带 60s 合并窗口 ≈ 被展示过的轮次数)。失真的是"把它当质量分"。
因此本次**不废弃它, 而是给它正确的角色**: 质量判断的分母。

### 谁有资格评价

**只有用它的 agent 能判断。** 人既不掌握 agent 当时的上下文, 也不可能逐条审核 ——
记忆量到千级时人工审核在物理上不可行。让 agent 自己操心"该记什么、哪条没记好"才是它该做的适配,
人只保留"错误记忆的最终裁决"这类低频、需担责的动作。

### 但它此前根本没被调度 (实测)

HXLoLis 项目全部会话日志统计 (解压 zstd 多帧后逐事件解析, 工具名取 `data.name`):
84 个会话 / **7440** 次工具调用 / `memory_*` 调用 **0 次**; 注入块 54 个。
最常用的是 `run_code` 5976、`bash` 679、`read` 223。

## Decision

### 原则一: 只记坏的, 沉默是常态 (决定形态, 不是措辞)

逼 agent 对每条召回都给判定是错的: "能召回到"本就是期望状态, 逐条确认信息量为零;
更糟的是它把**可选变成义务**, agent 会为交差而编造评价, 而噪声比没有信号更糟。
因此数据模型**只有负面字段**, 没有任何"有用"的入口。

### 原则二: "可选"写在模型看得见的地方

`memory_flag` 的描述里明确写"OPTIONAL, and rarely needed"、"silence is the normal, expected outcome"。
不进 `guidance` 的必做清单, 也不用"请评价以上记忆"的语气。

### 第一部分: 注入块末尾的**可操作入口**

`kernel/format-frame.ts` 新增 `memoryEntryHint(language)`, 由 `adapters/dsh/prestep.ts` 追加在注入块末尾:
"以上若与当前任务不相关或不够具体, 可调用 memory_search 换关键词再查 (可选, 不适用就忽略)。"
注入块是模型唯一一定会读到、且与记忆直接相关的位置 —— 把"还能继续查"做成每轮可见的**选项**。
选它而非 runner 钩子: 不依赖宿主钩子能力 (无版本漂移风险), 且天然与"可选"相容。

### 第二部分: agent 自评召回质量

新增工具 `memory_flag({ id, reason: "irrelevant" | "wrong", note? })` (DSH + MCP 两侧都注册):

- `irrelevant` = 召回但不相关 → **检索/排序问题**
- `wrong` = 内容不符或过时 → **内容问题, 需人审**

两类分开累加而非合成一个分数, 因为它们导向完全不同的修法。

数据模型 (`MemoryEntry.feedback`, 只记坏的):
```ts
interface RecallFeedback { irrelevant: number; wrong: number; }
```

自评**沿用用户当前配置的默认模型** (与 structurer/abstractor 同源), 不新增模型配置项。
覆盖范围**只到显式 memory_search 的召回**, 不含 always-on 注入 ——
后者是每轮无差别注入的常驻集合, 要求 agent 对它逐条表态会直接触发原则一所否掉的义务感。

### 第三部分: 标注真的影响检索

- **排序** (`kernel/feedback.ts` + `kernel/ranking.ts`): 因子
  `1 - (bad + α·prior) / (exposure + α)`, α=4, prior=0.2, 下限 0.2。
  贝叶斯平滑使小样本向中性收缩; 零曝光与零坏评都恒为 1 (老数据行为不变);
  下限保证"只降权不消失" —— 丢弃是治理动作, 不是排序动作。
- **治理** (`app/governance.ts`): `exposure >= 5` 且 `bad/exposure >= 0.5` 时产出 review 队列提议,
  **绝不自动改动记忆**。用比例而非绝对次数: 比例自带最小样本量约束, 避免"曝光 2 次错 2 次"就动手。
- **可见** (`gateway.flaggedMemories` + 面板"标注记录" tab): 展示每条被标注记忆的
  bad / 曝光 / 质量因子 —— 降权必须可解释, 治理动作不能是黑箱。

**重构**: `facade.ts` 因此超过 400 行上限, 治理动作的实现抽到 `app/governance.ts`
(facade 只留门面与编排), 与另两条职责线 (remember/recall、stats/digest) 分开。

## Alternatives considered

**人在面板上对记忆点赞/点踩 (本方案初稿的方向)。**
否掉。①发起者错了: 人不知道 agent 当时的上下文; ②不可扩展: 千级记忆人工逐条审核物理上不可行;
③方向错位: 这是把 agent 该做的适配工作转移给人。人保留的角色只有"错误记忆的最终裁决"。

**要求 agent 对每条召回都给出判定 (含"这条有用")。**
否掉。好的不需要反馈 —— 那是默认状态, 逐条确认信息量为零却要付 token;
更糟的是它把可选变成义务, 模型为交差而编造评价。**只记坏的, 沉默即正常**。

**由系统在检索后自动发起一次强制自评调用。**
否掉。同一原因: 它把"可选"变成默认成本, 并让 agent 认为每次检索都必须评价。
自评的发起权应在 agent (它只在**注意到问题**时才说)。

**前置部分用 runner 钩子而非注入块入口。**
否掉为首批实现。钩子更强制, 但依赖宿主是否开放该能力 (需先验证, 且随版本漂移);
注入块入口落在我们完全掌控的路径上。若实测调用率仍无改善, 再回来评估它。

**折叠成一个"质量分"字段 (single score) 而不是两类计数。**
否掉。`irrelevant` 指向排序问题 (调 channel 权重), `wrong` 指向内容问题 (要改写)。
合成一个数字会丢掉"该改哪里"这个指向, 而这正是反馈的主要用途。

**废弃 `reinforcement`。**
否掉。我们需要**分母**: 它恰好准确度量了曝光次数。它的问题是被误用作质量分, 不是存在本身。

**给模型一个 `memory_feedback` 工具让它自己想起来打分。**
方向保留但形态否掉: "打分"隐含逐条必答。改为只标坏的、显式可选的 `memory_flag`。

## Consequences

换来的: 第一次有了"召回质量"维度, 由唯一有资格判断的一方产生;
`reinforcement` 回到"曝光分母"的正确角色; 标注影响排序与治理, 形成闭环;
只收负面使采集成本近似为零 (沉默不花任何东西);
"可选"显式写在模型看得见处, 从形态上阻断义务感噪声。

付出的: 多一个工具的 schema 常驻成本; 新增字段动了 12 处存储链路
(类型/归一化/编解码/索引 DDL 与迁移/读回/内存 store/normalize 形状/frontmatter 白名单);
`facade.ts` 因此拆分出 `app/governance.ts`。

诚实边界:
- **本方案不能回答"记忆整体有没有用"** —— 只收负面仍是有偏采样
  (没被标注不代表没问题, 可能只是 agent 没注意)。真正的效果度量要靠可复现的对照实验
  (用 `hx-record-session-replay` 技能)。
- **天花板是调用率**: `memory_flag` 与 `memory_search` 共享同一个 0/7440 风险。
  第一部分的验收门禁就是 `memory_search` 调用率必须显著 > 0; 若长期为 0,
  本方案的回退位置是"纯曝光计数" (排序因子全部恒为 1, 功能退化但不产生错误数据)。
- 阈值 (0.5 / 曝光 5) 与平滑参数 (α=4) 是保守取值, 尚无真实标注数据校准。

## Testing

- `tests/s1/feedback.test.ts` (13 项): 归一化 (负数/NaN/非对象/正向字段被忽略)、
  `badCount`、质量因子的单调性与小样本收缩 (曝光 1 错 1 不被一棒打死)、下限 0.2、
  零曝光与零坏评恒为 1、`needsReview` 的双条件与边界。
  这组测试抓到一个真实 bug: 初版平滑公式把分子重复计入分母, 导致"全错"时因子也降不到 0.5 以下。
- `tests/s2/flag-recall.test.ts` (7 项): 两类分别累加、非法 reason 被拒 (没有正向入口)、
  not-found 不抛错、标注落盘且**重开进程后从真相文件读回一样**、
  曝光不足不提议 / 曝光够且占比够则产出 `sourceRun:"recall-feedback"` 的提议、
  **提议时目标记忆的内容与状态未被改动**、零标注零副作用 (不写字段、不产生队列项)。
- `tests/s1/frame-hint.test.ts` (5 项): 入口句中英都存在且标为可选、语气是"忽略"而非"必须/评价"、
  **入口句不干扰 `parseInjectedIds` 的条目 id 解析** (差量注入回归)。
- `tests/s2/mcp-http.test.ts` 改为断言工具集与 `MCP_TOOLS` 单一事实源一致 (不再写死数量)。
