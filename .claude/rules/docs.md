# 文档约束 (docs)

HX-Memory 本身是"记忆即文档"的系统, 它的文档规范比普通仓库更严。所有写盘文档遵守:

## 读者视角

- 文档写给未来的人类读者与 AI 读者, 不写过程痕迹 (谁做的、哪次会话、工具名、本地路径)。
- 不出现 `TODO` / `FIXME` 残留 (提交前必须清掉); 确需标记时写 `> [!NOTE] 未实现: ...` 并给出计划。
- 代码块标注语言; 引用仓库内文件用相对路径; 引用外部来源给 URL。

## 中文标点习惯 (与 HXLoLi 约定一致)

- 正文统一英文标点 + 半角括号: `,` `.` `:` `;` 后接中文保留一个空格 (`工具, 建议` `注意: 这里`)。
- 顿号 `、` 与书名号 `《》` `“”` 破折号 `—` 按原文保留。
- 行内代码 / 围栏 / URL / frontmatter 内一律不做转换。
- AI 生成后可用归一化脚本检查 (如 HXLoLi 的 format_cn_punct.py), 本仓库默认写作即合规。

## Markdown 结构

- 中文笔记标题用 `#` 单井号起步; 子节递增。英文文档同理。
- 表格必须有表头行与分隔行。
- 引用 >, 列表 -, 任务 - [ ] 均按原意。
- `docs/` 下每份文档声明: 目的、边界 (不写什么)、与代码的关系 (指向 src 相对路径)。

## 记忆正文约束 (本仓库产品的核心约束)

memory 正文 (daily/digest/rules) 是产品数据, 也是文档, 双重约束:
- 记忆条目必须可审计: 每条带 source 引用 (会话 id / 文件 / URL), 不许无源断言。
- 双时态: `validAt` (生效) 与 `assertedAt` (写入) 必须区分, 不允许只写一个。
- 规则 (rule) 必须有人工闸门记录: 谁在何时确认, 覆盖哪些实例; 机器提议 ≠ 已确认规则。
- 正文标点遵循上文; 关键词可中英混排但专有名词首现给原文。

## 禁止

- 禁止在文档/代码里出现 emoji 作为修饰 (house 风格; hooks 会检查)。
- 禁止软链接文档 (规则文件必须是实体)。
- 禁止把本仓库路径写进文档正文 (路径漂移); 用仓库相对路径。
