# Agent Note: DSH 面板可用性改造 (绑定预设 + 批次状态条 + 浏览排序)

Status: implemented

## Problem

DSH 设置区的两个面板被真实使用者判定为"没有使用欲望":

1. **绑定面板字段太多**。一条绑定要填 id / kind / scope / project / weight / max / signalWords
   七个字段, 而绝大多数真实需求只是"把跨项目规则绑上"或"把本项目经验绑上" —— 用户面对空白
   表单不知道该填什么, 于是干脆不配, 而"不配"就意味着该项目的记忆召回一直是空的。
2. **推广批次没有可观测性**。点一下"运行推广批次"只回一个计数, 状态不可见 (详见
   [推广批次可观测性](2026-09-11-generalization-observability.md)); 面板也不会在打开期间
   自动跟随后端变化。
3. **"记忆浏览"搜索框的结果看起来永远一样** —— 这是检索语义问题, 已在
   [检索目的分层](../architecture/2026-09-11-retrieval-purpose-and-alwayson-budget.md) 修复;
   面板侧需要相应地把"按相关性排序 + 空结果"如实呈现。

## Decision

**绑定面板: 一键预设 + 渐进披露。**

- 预设模板 (跨项目规则 / 本项目经验 / 跨工作区共享 / 只看教训与决策) 一键追加一条**已填好**
  的绑定 —— 覆盖绝大多数真实需求, 不需要理解七个字段的关系;
- **高级字段折叠**: 默认只显示 id / kind / scope / signalWords, weight / max 收进"高级";
- 保留字段保真与 dirty 跟踪 (编辑期间不覆盖用户输入) 的既有行为。

**审阅面板: 状态条 + 真实报告。**

- 顶部状态条轮询 `generalizationStatus`: 最近一次批次的时间/候选/簇/产出, AI 抽象是否可用,
  队列三段计数;
- 运行期间显示进行中状态, 结束后渲染**真实报告数字** (不再是"完成: N 条");
- `abstractor === false` 时显著提示"批次只能产出需要人工改写的草稿规则" —— 把降级显式化,
  而不是让用户以为功能坏了;
- 浏览结果按相关性显示序号 + kind/scope/project 徽标; **空结果显示明确的空状态**。

**样式**: 收敛到一套间距/徽标/空状态的 CSS, 全部挂在 `.hxmem-review` / `.hxmem-bindings`
根类下, 不引入新依赖、不污染宿主界面; 无 emoji (仓库 house 规则)。

## Alternatives considered

**让用户继续手填七个字段, 只加文档说明。** 文档解决不了"不想填"的问题; 而"不填"的代价
(该项目的记忆召回为空) 是不可见的。预设把最常见的三种意图变成一次点击。

**把 weight/max 直接删掉。** 它们是真实需要的旋钮 (限流、加权), 删掉就不能表达"这个源最多
注入 3 条"; 折叠比删除更合适。

**绑定面板改成向导 (分多步)。** 对"加一条规则绑定"这种一步操作来说, 向导比表单更慢;
预设 + 折叠已经覆盖, 不需要引入多步状态机。

**批次状态不入 RPC, 靠面板读本地日志。** 面板在 Web 侧, 读不到宿主文件系统; 且这会绕过
Facade/gateway 的统一语义, 让"面板"和"工具"看到不同的世界。

**浏览结果为空时回退显示"所有记忆"。** 会让"搜不到"和"搜到了但都不相关"无法区分, 掩盖
真实的相关性问题; 明确空状态是正确的诚实行为。

## Consequences

- 新用户配一条绑定的操作从"填 7 个字段"降到"点一个预设"; 不配绑定的项目仍有 always-on 保底。
- 推广批次从"黑盒按钮"变成"有数字、有状态、有失败解释"的功能, "0 条"不再是无信息的失败。
- 浏览结果不再出现"与查询无关但永远在前的规则", 空结果如实显示。
- 代价: 面板代码量增加 (`client/` 不受 400 行约束, 但阅读成本上升); 状态条每 5s 轮询一次
  `generalizationStatus` (只在面板可见时轮询, 后台标签页停止)。

## Testing

面板是视图层, 逻辑断言落在这三处:
`tests/s2/recall-separation.test.ts` 钉住浏览所依赖的 `purpose:"recall"` 语义;
`tests/s2/generalizer-trigger.test.ts` 钉住状态条读的 `status()` 形状与报告字段;
`tests/s2/client-rpc.test.ts` + `tests/s2/client-bundle.test.ts` 钉住 RPC 方法名集合与
构建产物模块 id (新增的 `generalizationStatus` 已加入 `remote-methods.ts`)。
真机门禁 `scripts/smoke-dsh.sh` 额外断言 `generalizationStatus` 可达且 `runGeneralization`
返回的漏斗报告字段齐全。
