# Agent Note: Wiki 式记忆后端 (候选, 未接线)

Status: proposed

## Problem

`src/wiki/` 有 **1017 行产品代码 + 533 行测试**, 但**未被任何产品路径引用** (全仓 `from ".../wiki/` 零命中)。
它既不在主线里, 也没有一篇 Note 说明"它为什么在那儿、什么条件下才启用" —— 于是它成了**悬空模块**:
读者看到 12 个源文件与 4 个测试文件, 无从判断它们属于"已上线"、"待实施"还是"已否决"。

## Proposal

**保持现状 (不接线), 并把状态写清楚**。它当前是"候选后端", 启用前提是**负载先到位**。

启用条件 (来自 `docs/wiki-blind-review.md` §6 的终局判定):

- 该范式要"一主题一页"才有收益, 而那需要"**同一主题出现多次**"的负载;
- 实测本项目语料里**主题基本只出现一次** (121/125 个主题互不重复) ⇒ 聚合无对象;
- 之后 §490~§496 又发现: 用**结构判据** (标题骨架) 量出的真实序列规模是 **10%** (31/313),
  而其中最大的一段是 `HX-Sagasu` 的 **18 轮迭代日志** —— 那是**唯一**被独立确证的序列。

⇒ 所以**不是"范式错了"**, 而是"**当前库里的可聚合结构太少**"。要重做对照, 先得有负载。

## Alternatives considered

**直接接线 (把 wiki 变成默认存储)。** 被否决: `docs/wiki-blind-review.md` §5 已声明**前一轮 A/B 结果作废**
(C 与 D 是同一段代码跑两遍; 命中判据可平凡操纵; 两臂 oracle 不同族)。在缺少可信对照之前接线 = 用未经验证的东西替掉验证过的。

**删掉它。** 被否决: 它的**代码骨架**经盲审评定为干净 (页 = 可整体重写的文件 / 读写共用地址 /
真相在文件 / 治理策略做成配置而非提示词), 且 `HX-Sagasu` 那段 18 轮序列证明范式**在合适负载上可行**。

**只保留 `docs/wiki-blind-review.md`, 删掉代码。** 被否决: 那会丢掉"可运行的骨架" ——
而重做题目的成本主要在**负载构造**与**对照设计**, 骨架重建反而是小头。

## 已知遗留 (诚实列出)

`docs/wiki-blind-review.md` §4 的 4 条至今**未修**, 而其中第 2 条**在主线里已经有了对应修法**:

| # | 遗留 | 现状 |
| --- | --- | --- |
| 1 | `matchPage` 无 IDF、无长度归一 | **未修** |
| 2 | **读-改-写非原子, `writeFileSync` 无 tmp+rename** | 主线 `markdown-codec.ts` 已用**原子写** (`writeFileAtomic`); **`src/wiki/page.ts:190` 仍是裸 `writeFileSync`** |
| 3 | `slug()` 把 `"接口/域名"`、`"A.B"` 压成同一键 | **未修** (假合并风险) |
| 4 | 命中判据依赖"页面正文含源条目首 32 字" | **未修** (自导自演残留, 见 §5) |

⚠ 第 2 条**不值得现在修**: wiki 未接线 ⇒ 没有任何真实数据走那条路径 ⇒ 风险是**潜在的**而不是正在发生的。
本 Note 记录它, 是为了"启用前先补上" —— 而不是主张现在动手。

## Acceptance criteria

本 Note **不主张实施**, 所以"验收"的对象是**状态记录本身**, 而不是代码:

1. 读者能在 3 分钟内回答三个问题: **它是什么** (候选记忆后端)、**为什么在这儿** (骨架干净但负载不足)、
   **什么条件下才接线** (先有"同一主题多条事实"的真实负载, 再按 §5 的修正方案重做对照)。
2. 启用 wiki 之前, `docs/wiki-blind-review.md` §4 的 4 条遗留必须**逐条处置** (修掉或写明为何不修)。
3. `scripts/wiki-precondition.ts` 的判定必须**先满足** (它现在用结构判据: 最大序列 18 / 覆盖率 10%)。
4. 若最终决定不启用, 本 Note 应改为 `Status: rejected` 并说明原因, 而不是被静默删除。

## Risks

| 风险 | 说明 |
| --- | --- |
| **悬空模块腐化** | 未接线的代码不会被任何真实使用检验 —— 主线的接口演进 (例如 `writeFileParts` 改原子写) 不会传导到它, 于是它会**悄悄落后**。本 Note 的"已知遗留"一节正是为此设的检查点。 |
| **被误读为"已上线"** | 12 个源文件 + 4 个测试文件容易被当作产品的一部分。**本 Note 的首要目的就是消除这个误读。** |
| **测试给人虚假的安全感** | `tests/s2/wiki*.test.ts` 有 30+ 项且全绿, 但它们只证明"骨架按设计工作", **不证明"范式在本负载上更好"** —— 后者已被 §5 声明**无法由当时的实验支持**。 |
| **重做对照的成本** | 主要成本在**构造负载**而不是改代码。若负载长期不存在, 这个 Note 会一直停在 `proposed` —— 那是**正确状态**, 不是失败。 |

## 与代码的关系

- 实现: `src/wiki/` (`address` / `compile` / `config` / `page` / `recall`)
- 判据脚本: `scripts/wiki-precondition.ts` (判定"负载是否已具备可聚合结构")
- 盲审与终局判定: `docs/wiki-blind-review.md`
- 序列规模的实测: 归档 §490 / §493 / §496
