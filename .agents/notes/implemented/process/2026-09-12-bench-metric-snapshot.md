# Agent Note: 评测指标快照 gate (防报告静默过期)

Status: implemented

## Problem

`docs/memory-benchmark-report.md` 里的指标表是**手抄**的。它描述的是"当前实现的行为",
但实现一改, 报告不会跟着变 —— 数字静默过期, 而"过期但看起来权威"比没有报告更糟。
同类问题在本仓库已有先例: `verify-docs` 就是为了拦住"引用了不存在的文件"而存在的。

## Decision

新增 `bench/snapshot.ts` + `bench/snapshot.json`:

- **只跑确定性臂**: A 纯词面 (`embedder: null`) 与 B 哈希近似语义 (`LexicalEmbedder`) ——
  它们不依赖本地嵌入服务与 LLM 代理, 因此在任何能拿到语料的机器上都可复现。
  真语义臂 (需要 127.0.0.1:4399) 与外部系统臂 (mem0 / basic-memory) **刻意不进快照**,
  否则 gate 会因服务未启动而假红。
- **另存三项结构指标**: 语料条目数 / 关系边总数 / 有 entities 的条目数 ——
  它们能抓住"写入路径退化"(例如 entities 又变回 0) 这类不体现在检索分数上的回归。
- **容差 0.005**: 指标是浮点且依赖分词与排序细节; 超过该值说明行为变了。
- 失败信息直接给出修法: 跑 `--write` 并同步更新报告表格 —— 强迫"改行为"与"改报告"同提交发生。
- 已挂进 `scripts/verify.sh` (docs gate 之后) 与 `package.json` (`verify-bench-snapshot`)。

## Alternatives considered

**把快照做成 CI 硬门禁。** 语料来自真实记忆库、含私人内容, 永不入库 (在 gitignore 的 `.tmp/` 下)。
CI 里必然没有它, 硬门禁只能二选一: 要么把私人记忆提交进仓库 (不可接受),
要么在 CI 里恒跳过 (等于没有门禁)。因此定位为**本地防漂移** gate, 并在输出里明说适用范围。

**把报告表格改成脚本生成 (报告即产物)。** 更能保证一致, 但报告除了指标还有结论、边界、
指标定义等大量散文化内容, 全量生成会让它退化成数据转储; 而"结论"恰恰是最需要人读的部分。

**只比对总分, 不比对结构指标。** 会漏掉一类真实回归: 实体抽取失效时检索总分几乎不变
(entities 不参与词面排序), 但图检索会悄悄失去全部边 —— 这正是本项目刚修过的问题。

## Consequences

- 改检索/抽取行为后, 本地 `verify.sh` 会在快照这一步失败, 直到显式确认新基线。
- 快照只覆盖 9 项指标, 是**抽样**而非全量 —— 它防的是"没人注意到行为变了", 不是"证明完全没变"。
- 缺语料时明确 skip 并打印原因 (含生成命令), 不会把"跳过"伪装成"通过"。

## Testing

- 一致时: `bench-snapshot: 9 项指标与快照一致 (容差 0.005)`, exit 0。
- 人为把 A 纯词面 R@1 改成 0.5: 报漂移项并 exit **1** (已实测)。
- 移走私有语料 (模拟 CI): 打印跳过原因, exit **0** (已实测)。
- 全量 `vitest run` 与 `verify-structure` / `verify-docs` 不受影响。
