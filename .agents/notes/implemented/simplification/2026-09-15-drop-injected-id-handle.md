# Agent Note: 注入行去掉行首 [id] 句柄 (保留行尾机器标记)

Status: implemented

## Problem

注入块里每条记忆都带一个行首句柄 `- [r2bb1aa1c3a89c121] 任何仓库 git 提交前…`,
理论上是"让模型能按 id 调用 memory_flag / memory_rule_propose"。代价是实打实的、
收益却是零:

- **代价 (实测, live store 9 条常驻)**: 整块 934 字符里, 行首句柄占 180 字符 (19%);
  正文本身只有 363 字符。行尾的 `<!--hx-memory:id=…-->` 标记另占 350 字符。
- **收益 (实测, 149 个会话 / 18138 次工具调用)**: `memory_flag` 全期只出现 **2 次**,
  `memory_rule_propose` **0 次**。而按 id 操作的能力真正被用到的场景是 `memory_search`
  返回之后 (那里仍会显示 id), 不是被动注入的常驻块。

即: 每轮都在为一句几乎从未被兑现的"可选能力"付 19% 的上下文税。

## Decision

`formatEntryLine` 从 `- [id] 内容 <!--hx-memory:id=id-->` 变成 `- 内容 <!--hx-memory:id=id-->`,
**只删行首句柄, 行尾机器标记原样保留**。

- 行尾标记是去重与差量注入的**唯一**判据 (`parseInjectedIds`), 删了会让
  "同一会话不重发常驻记忆"整体失效 —— 那正是 2026-09-11 修好的缺陷, 因此它必须留着。
- 这次是**纯减法**: 模型看到的是记忆内容本身, 代码看到的仍是稳定 id。
- 按 id 操作的能力不删, 只是不再"预支"给每一次注入: `memory_search` 的结果行
  仍带 id (那是模型主动检索后才需要它的场景)。

## Alternatives considered

**连行尾标记一起删掉 (真正做到"零元数据")。** 会使差量注入失去判据, 退回"整块文本判重",
也就是 2026-09-11 那篇修掉的缺陷。**否掉**。

**把标记换成更短的形态 (如 `<!--hx:id=…-->`)。** 省不了多少 (每条约 6 字符), 却要动
解析器、注入基线判据与已有会话历史里在用的标记格式 —— 旧会话里的标记一旦解析不出,
去重基线会退化。**不做**: 收益与风险不成比例。

**保留句柄但只在会话首轮给 (后续差量行不给)。** 去重依赖"已经出现过的 id", 与句柄无关,
所以技术上可行; 但首轮正是模型最没有"要不要标坏评"判断力的时刻, 而它带来的复杂度
(两种行格式) 会渗进解析与测试。**不做**。

**把句柄挪到行尾标记里一起展示 (如 `<!--hx-memory:id=…--> [id]`)。** 只是把同样的
字符换个位置, 省不下任何东西。

## Consequences

换来的: 9 条常驻注入从 934 → **754 字符** (省 180 字符 / 19%), 而模型看到的内容一字未少;
去重与差量注入行为完全不变 (标记未动)。

付出的: 注入块里不再直接显示 id, 模型若想对"被动注入的那条"调 `memory_flag` 需要先
`memory_search` 一次 (实测这条路径本来就极少发生, 也是本次决策的依据);
两条依赖旧格式的断言已按新语义更新。
