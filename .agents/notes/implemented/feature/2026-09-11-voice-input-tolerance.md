# Agent Note: 语音输入容错: 归一先于判定

Status: implemented

## Problem

本项目用户用**语音输入法**, 文本里天然带错别字与同音字。真实语料实例:
"多轮绘话"(会话)、"怎么确保它密等呢"(幂等)、"拍多个纸agent"(子 agent)、"get hup"(github)。

后果不是"读着别扭", 而是**字面链路整体失效**, 且不会报错:

- 意图正则用于匹配"提问的形状", 错字会让形状对不上 → 漏命中;
- 话题漂移用重叠系数, 短追问里一个错字就可能把同一话题推过阈值 → 误判成"换话题"并重复注入;
- 全文检索/覆盖率把"密等"当噪声 → 该召回的记忆一条都不召回。

## Decision

在**判定之前**做一次确定的归一 (`kernel/voice.ts`):

- `normalizeVoice`: 白名单映射 (仅收无歧义的同音对), 长词优先。
  用于意图判定、话题漂移、以及检索词的归一形。
- `voiceVariants`: 返回"原形 + 归一形 (+ 去口水话形)"。
  `retrieval/channels.queryTerms` 取**并集** —— 因为记忆里存的可能是错写, 也可能是规范写法,
  只取一边必然漏召回。
- 接点: `trigger/policy.detectIntent` / `topicDriftOf` (先归一), `retrieval/channels.queryTerms` (并集)。

**白名单而不是拼写检查器**: 臆造纠正比不纠正更危险 —— 把对的词改错会产生**静默的假相关**,
比漏召回更难发现。因此只收能追溯到真实语料或明确同音关系的条目, 且只处理 2 字 CJK 同音对
(单字替换会伤及正常词汇: "时间"/"实践"都合法)。

## Alternatives considered

- **上拼音/编辑距离做通用纠错**: 会产生大量假阳性, 而假阳性的后果是"静默的错召回",
  比"召回不到"更糟 (用户无法察觉)。**否掉**, 保留为后续可选增强。
- **只在检索侧归一 (不动判定侧)**: 那么意图与漂移仍然按错字判定 —— 用户抱怨的
  "多轮对话里反复插同一批"正好由漂移误判贡献。**否掉**。
- **把用户的错字在写入时就规范掉**: 真相文件是**用户的话**的存档,
  改写它等于篡改证据, 且会让"用户当时到底怎么说"这个信息永久丢失。**否掉** ——
  只在判定/检索的**读路径**归一。

## Consequences

换来的: 错字不再让链路整体失效; 检索同时覆盖错写与规范写法。

付出的: 归一表需要随真实语料增长 (每条都能追溯来源, 不做臆测);
`voiceVariants` 让检索词变多, 覆盖率分母随之变大 —— 实测无回归, 但这是一处需要持续观察的耦合。
未做: 单字错误与外语混写仍无覆盖。

## Testing

- `tests/s1/voice.test.ts`: 归一真实错字、不碰正确文本、幂等、变体集合、
  错字不回避意图命中、错字不把同话题误判成换话题、检索词同时含错写与规范写法。
