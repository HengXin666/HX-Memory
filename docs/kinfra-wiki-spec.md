# KInfra Memory "Wiki 存储范式" 精读与施工规格

> 目的: 精读腾讯 KM《KInfra Memory》第四章"存：把记忆编译成一座 Wiki"及其支撑章节, 把它的设计抽成**可直接施工的规格**, 供本仓库按该范式落地。
> 边界 (不写什么): 不复述全文; 不采信它的评测数字 (厂商单方声明, 非论文非可复现报告); 不做与其它系统的优劣比较; 本文只讲**它的设计本身**及其可实现形态。
> 与代码的关系: 本文是**设计输入**, 给出地址模型 / 页面解剖 / 工具链 / 配置 schema / 写入路径五份规格; 落地实现须另开 Agent Note 并遵守 ADR-002 (真相在文件) 与 ADR-003 (人工闸门)。

## 1. 命题: 为什么是"编译"而不是"存储"

它的第一性判断: **长期记忆的瓶颈不在存储量, 而在管理能力** —— 能否被准确定位、能否下钻到来源、能否被修正、能否随时间自我收敛。

由此推出存储形态的选择标准: 存储形态必须让后面三件事**在结构上成为可能**, 而不只是"能存下来"。

关键动词是**编译**: 同一段对话不在检索时临时拼装, 而在**写入时**就整理成"当前认为成立的知识"。

它的成本模型说得很直白 (第 3 节): 编译是**有意在写入侧花费 Token, 以换取读取侧的准确率**; 对"一次写入、长期反复读取"的场景, 这笔交换划算。它明确承认另一条路线的存在 (LightMem: Token 少一到两个数量级, 准确率也低约 15 个百分点), 并称之为**设计选择的差异, 不是优劣判断**。

这一条是全部设计的根: **写入贵、读取便宜且准**。

## 2. 存储规格: 三级地址

存储单元不是"一条 fact", 而是 **(目录, 页面, 小节)**。三条硬约束缺一不可:

1. **一主题一页** —— 物理聚合。同一主题的事实存在同一处, 一次读取就是一个完整判断, 不靠相似度把碎片拼回来, 因此**不存在拼漏**。
2. **读写共用同一个地址** —— 写入时确定"这条事实属于哪个目录的哪张页的哪个小节", 读取时回到同一个位置, 而不是在几百条相似记忆里重新猜哪条有效。
3. **页面是可整体重写的单元** —— 每张页有独立的正文预算、独立的时间线、独立的演化历史、独立的重写风险边界。

第三条是连锁反应的关键 —— 原文: "正因为地址稳定, '取'才可能分层下钻; 正因为页是可整体重写的单元, '变'才可能做页级重构"。**读、变、管三件事都是这个结构的结果, 不是并列堆上去的功能。**

它用状态机 (第 4.2 节) 说明强隔离: 偏好页增长不会挤掉项目页的空间, 改某人的动态不触碰项目页任何一个字。对比单文件式: 所有主题共用同一份有限的篇幅预算, **删哪一条由文件长度决定, 不是由重要性决定**。

## 3. 页面解剖: 六要素

一张记忆页面的六个要素 (第 4.2 节图):

| 要素 | 作用 |
| --- | --- |
| 目录 | 该页的语义归属, 决定路由与隔离边界 |
| 小节 | 页内结构; **证据与演化的最小粒度**, blame 落在这里 |
| 适用范围与来源 | 这条结论在什么条件下成立、从哪来 |
| 双向链接 | 跨主题关系的表达方式 |
| 时间线与证据入口 | 何时新增、被谁改写、为什么变 |
| 编辑入口 | 人握有最终编辑权的落点 |

双向链接值得单独强调, 它是**聚合的补充而非替代**: 同一实体的多条事实放进一页解决"簇内"问题; "A 提供了项目的接口文档"这类**跨主题**信息, 用一条双向链接表达, **存一次, 两边都能到达** —— 不必重复写两遍, 也不必丢掉一边。

## 4. 目录: 语法与词汇的边界

这是全部设计里最可操作的一条, 也是最容易被抄错的一条。

| 层 | 内容 | 谁定 |
| --- | --- | --- |
| **不可变 · 语法** | 三级地址、一主题一页、读写共用地址、证据链与演化记录、Dream 的四类治理动作 | 产品方 —— 这些是效果的保证, 不开放修改 |
| **可定义 · 词汇** | 有哪些目录、每类页面的模板、事实的路由规则、注入与治理策略 | 业务方 |

它给的类比是数据库: **提供引擎和建模范式, 业务定义自己的表结构**。

五类配置项 (第 4.4 节):

| 配置项 | 决定什么 | 示例 |
| --- | --- | --- |
| 目录 | 有哪几类记忆、各自的语义边界 | 电商客服增加 `objections/` |
| 页面模板 | 每类页面有哪些固定小节 | 客户页必须有「禁忌」「已承诺事项」两节 |
| 路由规则 | 什么样的事实进哪个目录 | 涉及金额与期限的事实一律进 `contracts/` |
| 注入策略 | 哪些页常驻上下文, 哪些按需召回 | 合规红线页常驻, 历史工单按需 |
| 治理策略 | 哪些页参与自动合并、哪些永不遗忘、哪些只读 | 法规页只读, 不可被对话写入 |

最后一项对强约束行业的价值在于: 它让"这类记忆不许被算法自动改写"成为**可配置的硬规则, 而不是靠提示词约束**。

三个行业的目录示例:

```text
电商客服                医疗健康                  法务合规
├── customers/         ├── patients/            ├── entities/
├── orders/            ├── conditions/          ├── contracts/
├── policies/          ├── medications/         ├── clauses/
├── objections/        ├── contraindications/   ├── precedents/
└── experiences/       └── care-plans/          └── regulations/
```

它同时给了反例警告: 目录**过粗会退回单文件式** (主题互相挤压), **过细则会让同一主题被拆散** (内聚性丢失)。落地建议是先跑默认目录, 再补 2–3 个领域目录。

## 5. 取: 分层下钻五级链

主流召回是 `query → embedding → top-k → 拼进 prompt`, 一次到底。它指出三个固有问题: **一次性**(拿到结果而非线索, 没法追问)、**不可审计**(为什么是这几条、漏了什么看不出来)、**成本恒定**(问"我喜欢什么咖啡"和问"这条规则什么时候改的"付一样的代价)。

它把记忆做成可逐层下钻的空间, **每一层都是一个工具**, 由 Agent 自己决定走多深:

```text
match_page      定位主题页                      ← 绝大多数问题从这里开始
 ↓
get_page        当前有效结论                    ← 绝大多数问题在这里结束
 ↓ (需要来源)
get_evidence    这条结论来自哪几轮对话
 ↓ (需要变化历史)
get_evolution   它何时新增、被谁改写、为什么变
 ↓ (需要核对原话)
search_dialogue / get_dialogue   未经改写的 user / assistant 原文
```

三个设计要点:

1. **宿主模型自主判断, 不新增"记忆 Agent"**。记忆能力以工具形式注册给宿主主 Agent, 判断权留在原来那个 Agent 手里 —— 它最清楚当前问题需不需要记忆。另起 memory agent 的代价是多一跳延迟、多一层信息损耗、多一个要独立对齐的决策主体。
2. **分层停止, 让准确率与成本解耦**。常驻上下文够用就直接回答 (零检索成本); 需要结论就读页面; 需要依据才继续下钻。它特意指出: 在 top-k 前置召回的架构里, **那条零成本路径在结构上根本不存在**。
3. **强制召回仍然可用**。分层是默认策略, 不是唯一策略; 合规核验等场景可在模型回答前强制执行召回。

**一条硬规则**: 对话片段的**摘要只用于定位"哪段对话", 不能被当作用户原话引用**。原话永远在未经改写的原始对话里。

## 6. 变: 双链路 + Dream

### 6.1 写入: 显式指令走快车道, 自动抽取搭便车

写入侧对宿主的要求只有一件事: **每轮对话结束后, 把 user message + assistant message 交出来**。其余分流全在内部完成。

- **快车道 (用户明确要求)**: "记住这件事" 写入待编译区, 下一轮即可参与召回, 随后编译进正式页面; "改掉这一句" 按**文本锚点直接修改正式页面**, 不经待编译区、不等编译周期, 改完立刻生效, 并同步刷新正文、时间线、演化记录与检索索引。
- **慢车道 (自动抽取)**: 复用宿主**本来就有的上下文压缩时机** —— 那时对话内容已在手边、模型调用本来就要发生, 记忆抽取的边际成本极低。未触发压缩的短会话, 由**每晚一次统一补偿兜底**。

设计原则: 用户明确表达的意图, 不应该和模型的猜测排在同一个队列里等批处理。

一次对话产出**两样东西**, 用途不同: **原始对话片段** (检索卡片, 用来定位"哪段对话") 与**经去重、消冲突、路由合并后的正式页面** (真相源, 用来回答"现在什么成立")。白天的写入**允许冗余**, 优先保证不丢信息、不阻塞对话; 结构性问题留给夜里。

### 6.2 Dream: 夜间的记忆自演化

白天快写必然积累结构性问题: 同一实体分裂成几张近义页、多张页各记一部分、若干经历共指一个没人归纳的判断、失效页仍在消耗召回预算。这些**不是"再写一条记忆"能解决的**, 需要跨页、全局、可重写的视角 —— 既慢又重, 不适合放在对话链路上。

Dream 做四件事:

| 动作 | 解决什么 | 关键机制 |
| --- | --- | --- |
| **合并** | 同一主题分散在多张近义页 | 四类页面信号连边 → 求连通分量得候选组 → 模型建议剔除噪声页 → 结合内置规则生成**带风险信号**的执行计划 → 执行时按时间先后写入而非拼接正文 |
| **综合** | 多段经历各不构成结论, 合起来才有规律 | 归纳出稳定偏好写回主题页; 原始事实与来源页全部保留 |
| **蒸馏** | 执行轨迹不可复用 | 提炼适用条件、已验证路径、失败经验、完成标准; 资源 ID 抽象为参数因而可迁移 |
| **遗忘** | 失效页仍消耗召回预算 | 失效页改写为**墓碑页**并指向合并目标, 保留历史链接兼容但不再参与召回 |

它给的关键判断: **"让模型决定合并哪两页并不难, 难的是敢让它真的执行"** —— 所以这条链路的重点不在自动化程度, 而在**每一步都可预览、可干预、可回溯**。并且 "会忘" 不是能力缺失: 它也是选择性遗忘与隐私删除的技术基础。

### 6.3 人类侧: 最终编辑权与一句话级溯源

Dream 是算法侧自演化, 人的修订是另一侧; **两者共享同一套地址和证据模型**, 所以人的一次修订, 算法能学到。

溯源的实现前提: **每一次页面写入都在小节粒度落了账** —— 这次写入让该小节新增了什么、删除了什么、由哪几条记忆和哪几轮原始对话驱动。它自己的说法是: **页面的每个小节都有自己的 git blame, 而且这份 blame 能追到源对话的原话**。

它还指出这条能力是数据飞轮的入口: 一次修订可记录"系统原来记了什么 / 用户认可的新状态 / 修改发生在哪个事实节点 / 这条记忆来自哪些对话", 进而归因为抽取、路由、更新、冲突、合并或隐私策略问题。

## 7. 管: 动作空间

目录、页面、双链、证据链带来更强的治理能力, 也带来成倍增长的决策量。它把这套决策形式化为一个**有限动作空间** (第 7.1 节):

```text
extract / skip                      要不要记
route / create / reuse              记到哪里
append / merge / update / retire    怎么变
link / cite                         和什么相关、依据是什么
recall / verify / stop              取到哪一层为止
```

它强调: 这个动作空间正好是"存 / 取 / 变"的并集 —— **它就是这套系统全部需要学习的东西**。

训练方法 (Node-Matched GRPO) 的要点: **不看回答, 只看记忆产物本身的变化** —— 同一段历史对话分别注入两条链路, 比较两份产物差异, 按三维度打分 (实际改动量 / 事实覆盖率 / **放置位置正确性**), 再把奖励信号回传到具体决策节点。两个设计: 多框架联合训练 (学到的是记忆管理能力本身, 而不是某框架的输出格式)、无需人工标注。

它给的一条结构性判据值得记住: **没有结构, 模型学不了; 没有模型, 结构跑不起来** —— 记忆管理之所以能被训练, 前提是它被形式化成有限、可判定的动作空间 (写到哪个 (目录, 页面, 小节)、是追加还是合并、该不该退役)。

## 8. 消融证据 (它自己的口径)

第 4.3 节给出读取路径消融, 固定回答模型与检索预算逐项拆结构:

| 读取路径配置 | 准确率 | 遗漏率 |
| --- | --- | --- |
| 完整 (页面 + 对话片段 + 下钻取证) | 86.5% | 1.1% |
| 去掉下钻取证工具 | 84.8% | 1.9% |
| 去掉上下文内对话片段 | 82.6% | 1.9% |
| 两条证据路径都去掉, 只剩页面 | 74.9% | 5.3% |
| 仅按分数排列记忆记录 (取消主题页组织) | 73.8% | 13.2% |

三个结论 (**方法论价值大于数值**):

1. 两条通往原始证据的路径**可以互相替代, 但不能替代页面本身** —— 单独去掉任一条损失在 2 点内, 两条都去掉则准确率骤降 11.6 点、遗漏率涨到 8 倍。
2. 页面组织本身值 2.5 点: 同样的证据、同样的预算, **按主题编译就是比按分数排列更容易被正确使用**。
3. **遗漏率的变化比准确率更能说明问题** —— 打散之后, 同一主题的事实要靠相似度重新拼回来, 拼不齐就是遗漏。

> 口径提醒: 上述数值是厂商单方声明, 不可作为本仓库的决策依据; 但**"同时看准确率与遗漏率"这个口径本身, 以及它的实验设计 (固定模型与预算)**, 是可直接照抄的方法。

## 9. 施工规格

把以上抽成五份规格, 每份都可直接落成代码。

### 9.1 地址模型

```text
MemoryAddress = (domain, page, section)
  domain   : 目录名, 业务可配 (默认 people/projects/preferences/rules/experiences)
  page     : 主题页, 一主题一页; 是重写与治理的最小单元
  section  : 页内小节; 是证据与 blame 的最小粒度
稳定地址 = 读写共用; 页可整体重写; 小节可单独追加与修订
```

### 9.2 页面文件形态

```text
memory/<domain>/<page>.md
  ---
  page: <page>            主题标识
  domain: <domain>
  scope: 适用范围
  updated: <ISO 时间>
  ---
  ## <section 1>          小节 = 证据粒度
  <正文: 当前认为成立的结论>
  - 来源: <episode 引用 / 证据入口>
  - 适用范围: <边界条件>
  - 时间线: <新增 / 改写 / 退役记录>

  ## <section 2>
  ...

  ## 链接
  [[<其它页>]]            双向链接: 跨主题关系, 存一次两边可达
```

### 9.3 工具链 (取)

```text
match_page(query)        → 候选主题页 + 匹配理由
get_page(page)           → 该页当前有效结论 (默认终点的上一层)
get_evidence(section)    → 驱动该小节写入的对话轮次引用
get_evolution(section)   → 该小节的新增 / 改写 / 退役历史
search_dialogue(query)   → 未经改写的原始对话检索
get_dialogue(id)         → 单轮原文
```

约定: 前两级覆盖绝大多数请求; 后四级**按需下钻**, 由宿主模型自主决定走多深; 摘要永不当作原话引用。

### 9.4 配置 schema

```text
{
  domains: [ { name, description, semantics } ]        目录与语义边界
  pageTemplates: { <domain>: [ section, ... ] }        每类页面的固定小节
  routing: [ { when: <条件>, to: <domain> } ]           事实路由规则
  injection: { resident: [<page>...], onDemand: [<page>...] }   常驻 / 按需
  governance: { <domain>: "mergeable" | "frozen" | "readonly" } 治理策略
}
```

不可开放修改的部分 (语法): 三级地址、一主题一页、读写共用地址、证据链与演化记录、Dream 的四类动作。

### 9.5 写入路径

```text
每轮对话结束
 ├─ 快车道: 显式指令
 │   ├─ 「记住这件事」→ 待编译区 (下一轮即可召回) → 编译进正式页
 │   └─ 「改掉这一句」→ 文本锚点直接改正式页 (同步正文/时间线/演化/索引)
 └─ 慢车道: 自动抽取
     ├─ 搭宿主既有上下文压缩的便车 (边际成本极低)
     └─ 未触发压缩 → 每晚统一补偿

产出两样: 原始对话片段 (定位用) + 正式页面 (真相源)
白天允许冗余; 结构性问题交给夜间 Dream
```

### 9.6 最小落地顺序

1. **地址与页面**: 先有 (domain, page, section) 与页面文件读写, 才有后面一切。
2. **编译写入**: 自动抽取把对话整理进"正确的 (目录, 页面, 小节)"。
3. **分层工具**: match_page / get_page 先上, 覆盖大多数问题; 证据与演化层随后。
4. **审计口径**: 同时记**准确率与遗漏率**, 且固定回答模型与检索预算 (照抄它的实验设计)。
