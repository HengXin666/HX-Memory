# Agent Note: 跨工作区记忆: 仓库级项目键与共享作用域

Status: implemented

## Problem

记忆的"分层"要成立, 前提是**同一条记忆能在它该生效的范围里被找到**。原实现有两条裂缝:

1. **项目键 = 工作目录的目录名。** 在 monorepo 里, 同一个仓库的每个子包是一个目录,
   于是记忆按子包碎片化: 在一个子包沉淀的项目经验, 换到该仓库另一个子包工作时"不属于
   这个项目", 绑定、always-on 与项目内召回全部看不到。
2. **跨工作区共享层形同虚设。** `scope:"agent"` 的条目虽然存在, 但 `selectAlwaysOn`
   只收"项目内的 fact/preference/decision"与已确认规则, **完全忽略 agent scope** ——
   用户想表达"这条经验适用于我所有工作区"时, 它既不会常驻注入, 也没有别的通道保证生效。

## Decision

**项目键改为"仓库名"** (`projectKeyOfCwd`):

- 用 `git rev-parse --show-toplevel` 取仓库根目录, 再取它的目录名;
- 非 git 目录 / 无 git / 无权限时**回退到目录名** (必须有一个稳定的键, 不能没有);
- 结果按规范化 cwd 缓存 (会话开始与预步都会问这个键);
- git 执行器可注入 —— 让语义可被单测钉住, 不必真的建仓库。

同一仓库的任意子目录因此得到**同一个**项目键; 跨仓库仍然隔离。

**`scope:"agent"` 的 fact/preference 纳入 always-on 候选**: 它们是跨工作区共享层,
不属于任何项目, 因此对每个项目都常驻候选 (与项目事实同组竞争分仓后的预算)。

## Alternatives considered

**继续用目录名, 靠用户手动配置绑定来弥补。** 把系统自身能确定的语义 (同一个仓库)
转嫁给用户配置, 而用户未必知道记忆按目录分裂 —— 这正是"绑定面板让人觉得没用"的一部分。

**项目键取 git remote URL 或仓库根绝对路径。** remote 可能不存在 (本地仓库) 或换域名后失效;
绝对路径不可移植 (换机器/换 clone 目录后记忆全部落空)。目录名是这两者之间最稳的折中。
代价: 两个不同路径下的同名仓库会合并 —— 这是可接受的 (它们本来就极可能是同一个项目)。

**每次取键都同步调 git (不缓存)。** `projectOfSession` 在预步路径上每轮都会被调用,
每次 fork 一个 git 进程是明显的浪费; 按 cwd 缓存没有语义风险 (同一会话内 cwd 不变)。

**给共享层单独开一个 scope 或单独的注入通道。** `scope:"agent"` 已经表达了"不属于任何项目"
的语义, 缺的只是"被 always-on 收进来"; 新增机制不如把既有作用域接上。

**把 agent scope 的所有 kind 都收进 always-on。** lesson 是"具体历史", 由意图通道按需召回
更合适 (与既有决策一致); 常驻只放 fact/preference 这类短小稳定的事实与偏好。

## Consequences

- 在 monorepo 任意子目录工作, 都能看到该仓库沉淀的项目记忆 (此前会碎片化)。
- 非 git 目录行为与之前一致 (目录名), 因此既有数据与测试不受影响。
- 用户可以真正使用"跨工作区"这一层: 用 `scope:"agent"` 存的事实/偏好对每个项目都常驻。
- 代价: 项目键的语义从"目录"变成"仓库", 同名仓库会合并; 已在 `runtime.ts` 文件头注释
  与本节写明。取键会短暂 fork git (3s 超时, 失败回退), 且结果缓存。

## Testing

`tests/s2/project-plumbing.test.ts`: git 可用时 monorepo 子包与仓库根得到同一个键;
git 失败时回退目录名; 无 cwd 时 undefined。
`tests/s2/recall-separation.test.ts`: `scope:"agent"` 的事实对任意项目常驻注入,
而别的项目的 `scope:"project"` 事实不注入。
