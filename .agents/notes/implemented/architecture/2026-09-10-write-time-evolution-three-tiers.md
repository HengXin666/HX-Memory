# Agent Note: 写入期演化分三档 (合并 / 显式取代 / 冲突标记), 规则豁免

Status: implemented

## Problem

"记忆会自己更新"如果做成"新记忆自动推翻旧记忆", 会同时吞掉两种完全不同的情况: 用户**改主意了** (应该取代), 与用户只是**说得更细了** (应该保留双方)。反过来什么都不做的话, 旧结论会和新结论一起被注入, 模型看到的是自相矛盾的记忆。调研也发现这不是我们独有的难题: mem0 OSS v3 干脆退回 ADD-only。

## Decision

按**证据强度**分三档 (`src/evolution/evolve.ts`):

1. **duplicate (自动, 只强化)**: 归一化指纹相同, 或候选覆盖率 ≥ 0.75, 或语义余弦 ≥ 0.95 (且有 ≥5 词证据门)。不重复落盘, 强化老条目并合并新标签/实体。
2. **supersede (自动, 写演化链)**: 必须**四条同时成立** —— 显式更新信号 (改为/不再/废弃/替换为…)、同一种类、`validAt` 不倒退、覆盖率 ≥ 0.5。新条目带 `supersedes`, 旧条目置 `superseded` + `supersededBy` (**不删除**, `history()` 可查, 检索只注入最新 active 版本)。
3. **contradict (只标记, 不裁决)**: 数字不一致或极性相反且无更新信号 → 双向 `contradicts` 边, **两条都保持 active**, 谁对谁错交给人。

**规则豁免是硬约束**: 候选是 rule → 只落盘; 目标是 rule → 只标记冲突, 状态绝不由机器改。

## Alternatives considered

**LLM 全权裁决 (mem0 早期 / A-MEM)。** 能力最强, 但需要调用模型、结果不确定、且失败时没有可回退的确定性语义; 还要额外定义"模型改错了怎么回滚"。现在是确定性规则做自动档, LLM 只作为**建议**来源 (见 proposed 的裁决器提案)。

**只做去重, 完全不做演化。** 最安全, 但"我把上限改成 50"这类明确更新会变成两条并存的记忆, 检索时随机注入其中一条 —— 比不做还糟。

**按相似度阈值自动取代 (纯向量阈值)。** 实测不可靠: 近义重述的余弦也可能很高, 会被误判成"推翻"。取代必须有**显式语言信号**, 这是本决策的核心。

## Consequences

"换个说法重记"不再产生重复; 显式更新能自动生效且历史可查; 真正的矛盾显式暴露而不是静默覆盖。代价是: 需要语义判定的冲突 (措辞相反但数字相同) 只被标记而不会被自动解决, 会积累在 `contradicts` 边里等人处理。
