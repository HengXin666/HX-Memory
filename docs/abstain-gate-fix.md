# 弃权闸门误杀修复 + 检索层职责拆分

> 目的: 记录一次**未提交改动引入的静默回归**的定位过程与其修复, 以及随之完成的检索层文件拆分。
> 边界 (不写什么): 不讨论检索算法选型; 不复述证据链设计 (见 evidence-chain.md)。
> 与代码的关系: 修复落在 `src/retrieval/gate.ts` (新) 与 `src/retrieval/hybrid.ts`; 拆分新增 `gate.ts` / `lifecycle.ts` / `capabilities.ts` / `app/evidence.ts` / `app/facade-queries.ts` / `app/remember-flow.ts` / `kernel/ports-engines.ts`。

## 1. 一次被误判为"既有失败"的回归

现象: `tests/conformance/paraphrase-recall.test.ts` 断言"开启离线语义后 Recall@3 >= 0.8", 实测 **0.600**。

我先前的处置是错的 —— 我用 `git stash` **只隔离了自己改的 2 个文件**, 看到失败仍在, 就判定它"改动前就存在"。实际用 `git stash -u -- src tests` **隔离全部未提交改动**后:

| 状态 | 结果 |
| --- | --- |
| HEAD 基线 (全部改动已 stash) | **4 passed** (Recall@3 >= 0.8) |
| 含未提交改动 | 1 failed (0.600) |

**结论: 它不是既有失败, 是工作区里某处未提交改动引入的回归。** 教训: 判定"既有失败"必须隔离**全部**未提交改动, 而不是只隔离自己的 —— 否则会把别人的回归认成基线。

## 2. 逐文件二分定位

对 10 个可能相关的文件逐个 `git checkout` 后重跑该测试:

```text
>>> 罪魁: src/retrieval/hybrid.ts
```

即 `verify-structure` 一直在报"433 行超限"的那个文件 —— **两个症状同源**。

## 3. 根因: 弃权闸门误杀语义召回

`hybrid.ts` 里新增的弃权闸门用**字面**重合判断"库里有没有这条知识"。而向量通道存在的意义恰恰是"字面不重合也能召回" —— 两者直接冲突。

实测 (`.tmp/bench/diagnose-abstain.ts`): 传 `coverageMode:"candidate"` 可跳过闸门, 于是能看到闸门生效前的真实命中。

| 指标 | 数值 |
| --- | --- |
| 被闸门清空的查询 | 6 个 |
| 其中闸门前**确实召回了正确条目** | **6 个 (100%)** |
| 其中闸门前也没有正确条目 | **0 个** |

逐例全部是向量通道的正确召回:

```text
"要不要给并发加个天花板"     → [vector] 容器并发要显式设置上限
"DB 连接拿不到时的兜底策略"   → [vector] 数据库连接池超时要设置重试与熔断
"缓存什么时候过期"           → [vector] 缓存过期时间统一设为 60 秒
"多实例调度同一个 job 会打架" → [vector] 定时任务必须加分布式锁防止重复执行
"出事之前要先想好怎么退回去"  → [vector] 回滚方案必须在发布前准备好
```

而**真正的库外问题** (`量子退相干实验装置校准` / `Rust 的 tokio 运行时怎么选`) 在闸门**之前**就已经是 0 条 —— 闸门对它们毫无贡献。

**误杀率 6/6, 判对率 0/6。** 这不是"闸门太严", 是闸门的判据维度选错了: 它用字面证据否决了语义证据。

## 4. 修法

闸门增加**语义支持**判据, 与字面支持**并列** (任一条成立即不弃权):

```text
literalSupport  = 命中条目包含查询的某个"具体词"
                  (拉丁/数字标识符, 或 >= 3 字 CJK; 2 字 CJK 太常见, 不足以证明)
semanticSupport = 有命中是通过 vector 通道进来的
  ↑ 取**通道证据**而不是重算相似度: 通道是候选进入结果集的既有依据,
    复用它才能保证两处口径不分叉 (同类教训: 索引与查询必须共用同一分词函数)
```

效果:

| 指标 | 修复前 | 修复后 |
| --- | --- | --- |
| 离线语义 Recall@3 | 0.600 | **0.900** |
| 闸门误杀数 | 6 | **0** |
| 真库外问题仍弃权 | 是 | **是** (未被削弱) |

闸门**本意完好** —— 它防的是"把不知道伪装成知道", 修完这条依然成立。

## 9. 中文场景失效修复 + CLI 入口 (2026-09-18 续)

### 9.1 一个只有真实数据才暴露的缺陷: 闸门在中文上整体失效

用真实库跑 CLI `search` 时发现: **库外中文查询 "量子退相干实验装置校准" 返回了 5 条完全无关的记忆**, 未弃权。

诊断 (`.tmp/bench/diag-abstain-real3.ts`):

```text
queryTerms.weighted = ["量子","相干","实验","装置","校准"]
discriminativeTerms → []        ← 判据要求 "拉丁/数字 或 >= 3 字 CJK"
fallbackCjkTerms    → 全部 5 个  ← 但它们全是 2 字
```

**中文短语几乎全是 2 字词**, 于是 ">= 3 字才算具体词" 这条判据把整个查询滤空, 而旧实现把
`specific.length === 0` 当作"无判据 → 不弃权" —— **闸门在所有中文查询上都不判定**。中文是主场景, 等于闸门无用。

修法: 判据**降级而不是放弃** —— 没有具体词时退回"多字 CJK 内容词"这一档; 连内容词都没有 (纯虚词/单字) 才按"不弃权"处理。

### 9.2 第二个缺陷: 保底通道被误杀

修完 9.1 后发现 `purpose="inject"` 下**所有查询都被清空**。诊断:

```text
purpose=inject 闸门前 5 条: 全部是 rules 通道 [rules] 记忆触发须设无条件保底注入通道
                                          [rules] 派生索引必须可全量重建
                                          [rules] 全文检索索引与查询必须共用同一分词函数 ...
```

规则正文里自然不含查询词 → 闸门判"无支持" → **把整份结果清空**。
而规则是"跨项目不变量必须永远在场" (ADR-006 保底通道), 它们的在场**本就不该由当前查询的相关性决定**。

修法: **rules 通道的条目不参与弃权判定** —— 它们对这个问题的回答是"既不支持也不反对"。

### 9.3 CLI 入口 (人侧第二条通道)

新增两个子命令 (此前 CLI 只能直连存储, 会绕过使用层语义):

| 命令 | 作用 | 退出码 |
| --- | --- | --- |
| `search --text <q> [--limit N]` | 与面板/工具同一条检索语义; 弃权时输出 `No relevant memory found.`; 降级写 stderr | 0 |
| `evidence --id <id>` | 追来源; **0 = 可完整溯源, 2 = 溯源不完整, 1 = 条目不存在** | 见左 |

退出码三分让脚本能据它决定"要不要人工核对", 而不是靠解析输出文本。

真实库实测:

```text
$ hx-memory evidence --root ~/.dsh/hx-memory --id m1d65c7af3ea84838
[m1d65c7af3ea84838] HX-Memory 弃权闸门误杀修复 + 检索层拆分 ...
source: session:tool
traceable: no
reason: 该条目没有记录血缘 (写入时未捕获 episode 引用)
$ echo $?   → 2
```

即: 对**历史数据**如实报告"不完整"并说明原因, 而非假装成功。
