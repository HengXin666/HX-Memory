# Agent Note: 触发层 (四通道), 让记忆在"模型没意识到要查"时也生效

Status: implemented

## Problem

本项目的记忆此前有两条通路: 项目声明了 `MemoryBinding` 的, 由 Binder 在 `agent/pre-step` 确定性注入; 没声明的, 只剩会话开始的一段指引 + `memory_search` 工具 —— 也就是把"记忆是否生效"交给模型的概率判断。

这留下三个真实缺口:

1. **新项目/未配置绑定的项目完全没有记忆** —— 而这是最常见的状态 (没人会为每个仓库先配一遍拓扑);
2. **模型想不起来要查**。它无法可靠区分"我不知道"与"我知道但记错了", 于是默认用参数记忆作答; 工具调用又受提示词、上下文压力、任务形态影响, 同一份记忆在不同轮次表现不一致;
3. **没有可解释性**: "这轮为什么没注入记忆" 无从回答。

## Decision

新增触发层 `src/trigger/policy.ts`, 把"何时注入"变成**代码判定 + 可审计决策**, 四通道并存:

1. **always-on 保底**: 跨项目已确认规则 + 本项目关键事实/偏好/决策 (以及 `scope:"agent"` 的跨工作区事实/偏好), **不看意图, 无条件注入**。预算 400 token 且**分仓**: 规则组最多占 60%, 其余留给项目事实 —— 规则按 score 100 会吃光全部预算, 真正随任务变化的事实一条都进不来 (见 [跨工作区记忆](2026-09-11-repo-stable-project-key-and-shared-scope.md))。这是"模型完全没意识到要查"时的唯一保证, 也是唯一不依赖任何判定的通道。
   修正 (2026-09-11): "无条件注入"指的是**不被意图门控**, 不等于"每轮重发" ——
   同一会话内常驻记忆只进一次, 之后只补真正的新条目 (见 [注入去重与差量注入](../../bug-fix/2026-09-11-injection-dedupe-and-delta.md))。
   实测该通道此前平均每 2.5 轮重发一次同一批内容, 逐轮在上下文里累积。
2. **意图门控**: 6 类"回忆型提问的形状"(决策理由 / 接续进度 / 约定偏好 / 踩坑教训 / 项目背景 / 既有做法), 命中即注入。匹配的是**提问的句式**而不是知识内容 —— 内容词永远列不全, 句式是有限且稳定的。**不依赖项目是否声明过绑定**。
   修正 (2026-09-11): 模式分成两层 —— **句式形状**命中即算; **裸话题词** (规范/偏好/踩过) 必须与提问形状**同分句**才算。此前混作一层时, "…目录命名规范…"这类列举规格的陈述句被误判成"在问约定"。
   同时置信度改为 `1 - 0.5^命中数` (1 条 → 0.50), `minConfidence` 默认值从 0.34 提到 0.5 —— 旧默认值恰好等于旧公式的硬下限, 门控对任何命中恒真, 从未拦下过一条。
   判定与意图库已拆到 `src/trigger/intents.ts` (`policy.ts` 只留决策与预算, 并重新导出保持 API 不变)。
   见 [意图判定分层](2026-09-11-intent-shape-vs-topic.md)。
3. **话题漂移重查**: 漂移 ≥ 0.8 时强制重查 (旧注入的内容已不适用); 短追问与指代型追问判为同话题。
4. **去重**: 同话题连续追问不重复注入 (基于话题漂移); 另有**跨轮条目级去重**:
   调用方把"本会话已注入过的条目 id"交给 Binder 排除, 常驻记忆只进一次。两层的判据不同 ——
   前者判"这轮该不该查", 后者判"要发的东西里哪些已经发过了"。

配套改动: `Binder` 在**没有任何绑定**时改走通用触发通道 (此前直接返回空); `TriggerDecision` 记录 `mode/intent/confidence/topicDrift/reason/budgetTokens`, 让"为什么没注入"和"注入了什么"一样可查; `Binder.warm()` 增加 always-on 缓存的异步预热 (预步是同步判定点, 不预热则首轮无保底 —— 而那正是最需要保底的时刻), 仍然带硬时限。

后续修正 (2026-09-11): 意图召回改走 `purpose:"recall"` —— 它要的是"这件事的具体历史",
不该把不变量保底再垫一遍 (规则已由 always-on 通道注入); 规则保底只保留在 `purpose:"inject"`
路径上 (见 [检索目的分层](2026-09-11-retrieval-purpose-and-alwayson-budget.md))。

诚实边界: 意图库是模式匹配, 覆盖不到的表达会漏 (可扩 `DEFAULT_INTENTS`); 中文指代型追问 ("那这个下限呢") 字面无重合, 靠显式规则兜底; always-on 预热超时则当轮退化为无保底, 下一轮补齐。

同时按 MCP 工具设计的最佳实践改写了指引与 `memory_search` 描述: 明确写出**什么样的提问该去查**(问理由/问上次/问约定/问既有做法), 并说明"查不到就是真的没有, 不要编造"。代码通道给通用保底, 意识引导给精度, 两条并行。

## Alternatives considered

**只靠工具调用 (让模型自觉)。** 市面多数方案的做法 (mem0 SDK、Graphiti、claude-mem、Basic Memory、LangMem、MCP memory server)。实现最省事, 但可靠性交给概率判断 —— 实测对照中旧线 10 轮只有 6 轮命中。保留工具作为"精度增强", 但不作为唯一通道。

**无条件全量注入 (Letta 的 `system/`、VCP 的日记占位符)。** 保证必进, 但常驻内容吃预算, 且触发 "lost in the middle"; 全量注入在记忆增长后不可持续。改为: always-on 只放**不变量**(已确认规则 + 关键事实), 具体历史按需召回。

**只扩关键词表 (像 ai-memory 的 20+16+27 条模式)。** 方向正确 (hook 强制 + 门控 + 漂移 + 预算), 但纯关键词表匹配的是**知识内容**, 词表永远追不上表达; 本实现改为匹配**提问形状**并叠加 always-on 保底。

**把 always-on 也放进意图门控 (省事)。** 会让"模型没意识到"时再次失去保底 —— 那正是本决策要消除的场景。因此 always-on 与意图通道是**并行叠加**而非二选一 (实现中发现: 只给 always-on 会让用户问"上次怎么解决的"拿不到那条 lesson)。

**用两条阈值线 (相似线 + 切换线) 判话题。** 实测在中文短查询上会出现"既不算相似也不算切换"的夹缝; 改为单条漂移阈值, 并把度量从 Jaccard 换成**重叠系数** —— 连续追问往往很短, Jaccard 会把同话题的漂移高估到 0.6+ 与真正换话题 (1.0) 挤在一起。

## Consequences

记忆从"要用户先配好、模型想起来才查"变成"默认就有保底, 且换话题/问历史时自动深挖"; 每次决策都留痕, 可解释"为什么这轮没注入"。代价: ①always-on 占用最多 400 token 预算/会话 (差量注入后不再逐轮重花, 可用绑定/设置收紧); ②意图库需要随表达习惯维护; ③首轮预热有 50ms 硬时限的降级窗口。

**诚实边界 (2026-09 实测)**: 该通道的"意识引导"被自己的措辞削弱过 —— 指引原文写"系统会自动注入…你不需要为它做任何事", 与紧邻的"主动调用 memory_search"直接矛盾; 实测主动检索率只有 **6.7%** (8 次 / 119 条用户消息), 34 个会话里只有 7 个出现过。措辞已改为"自动注入只覆盖常驻不变量, 具体历史必须主动查"。

**意图正则的价值曾是待办, 已处理 (2026-09-11)**: 实测 61 条真实人类消息命中 11 条 (17.5%), 置信度 11 条全部卡在下限 0.34。当时的结论是"价值存疑"。后续实测**推翻了删除方案** —— 删掉会让正例召回 7/8 → 6/8, 并留下"无绑定项目无任何触发路径"的空洞; 正确做法是修判定精度 (分层 + 同分句), 修完正例召回 8/8、两处真实长文本误报全部消除。详见 [意图判定分层](2026-09-11-intent-shape-vs-topic.md)。

## Testing

`tests/s1/trigger-policy.test.ts` (20 项): 四通道各自的注入/跳过判定、意图命中与不误判 (普通指令)、**话题词须与提问形状同分句**、**置信度反映证据强度而非钉死在下限**、漂移度量性质 (同话题 < 阈值 ≤ 换话题; 短追问不被误判)、always-on 选择 (未确认规则排除、预算截断、lesson 不常驻)、决策字段完整可审计、意图库可扩展。
`tests/s2/trigger-injection.test.ts` (4 项): 端到端 —— **项目零绑定**时普通指令仍拿到 always-on 规则; 回忆型提问能召回具体 lesson; 同话题不重复注入而换话题重查; 每次注入都留下可审计决策。
