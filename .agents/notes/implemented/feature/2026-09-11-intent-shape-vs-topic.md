# Agent Note: 意图判定 — 句式形状与话题词分层, 置信度去下限

Status: implemented

## Problem

触发层的意图通道 (`detectIntent`) 用正则判断"这轮是不是在问历史"。此前把两类可靠性完全不同的
模式混在一张表里:

- **句式形状** (`为什么我们…` / `上次怎么解决的`) —— 句式本身就在表达"我在问";
- **裸话题词** (`约定|规范|惯例|标准|风格|习惯|偏好` / `踩过|踩坑|坑`) —— 词只提供话题。

于是**陈述句里出现话题词就被判成提问**。在 61 条真实人类消息 (从 41 个 HXLoLis 会话的
zstd 多帧日志里解出) 上实测:

| 项 | 值 |
| --- | --- |
| 命中 | 11/63 = 17.5% |
| 置信度分布 | **11 条全部恰好 0.34** (旧公式的硬下限) |
| 通过 `minConfidence` 门控 | **11/11** (阈值从未拦下过任何一条) |

三处具体的坏:

1. **误报来自裸词表**。"…专用md格式/文风/目录命名**规范**/HXLoLiTag…" 只是**列举规格**,
   却被判成"在问约定" → 每轮多注入 300 token 无关记忆 (实测该查询确实召回了
   "freebuff 账号轮换"这类完全无关的条目)。
2. **置信度不携带信息**。`confidence = max(0.34, hits/patterns.length)`, 而
   `minConfidence` 默认值**也是 0.34** —— "置信度 >= 阈值"对任何命中恒真, 门控是死的。
3. **漏掉真实形状**。"我们之前遇到过幂等问题吗" 是典型回忆型提问, 但 `prior-art` 要求
   显式"有没有/是否/曾经", 整条漏掉。

## Decision

### 一、意图模式分两层 (句式形状 / 裸话题词)

`TriggerIntent` 增加 `topicPatterns`: 话题词模式**必须与提问形状同现**才计入。
把三张裸词表 (`convention-preference`、`pitfall-avoidance`、`project-status#1`) 挪进这一层。

### 二、同现的门槛是**同分句**, 不是同文本

第一版按"整段文本同现"判定, 实测**仍然误报**: 一条 300 字的消息里,
"…目录命名`规范`…" (话题词) 与 "…`如何`开始训练…" (形状词) 分处两个不相干的句子。
同现 != 相关 —— 这是袋装正则的固有极限。收到分句以内 (`clausesOf` 按中英标点切句)
才把它消除, 而真实回忆型提问不受影响 (8/8)。

### 三、置信度改成 `1 - 0.5^命中数`, 并去掉 0.34 下限

旧公式 `hits / patterns.length` 的**分母随覆盖度增长**: 给某个意图多补几条模式,
反而降低同一份证据的置信度 —— 语义是反的。
新刻度: 1 条 → 0.50, 2 条 → 0.75, 3 条 → 0.875, 上限仍为 1。

`minConfidence` 默认值从 0.34 改为 **0.5**。这不是收紧, 而是**让参数第一次真的能用**:
旧默认值恰好等于旧公式的硬下限, 所以门控永远为真; 现在 0.5 = "至少一条模式命中",
把它抬到 0.75 即可要求"至少两条独立模式" (实测该设置下 1 条命中的提问不再注入)。

### 四、拆出 `src/trigger/intents.ts`

`policy.ts` 因本次改动达到 445 行, 超仓库 400 行上限。意图库与判定拆到独立文件
(`policy.ts` 只留决策与预算), 变化原因不同: 前者随"提问形状的认知"变, 后者随"决策策略"变。
对外 API 不变 (`policy.ts` 重新导出), 调用方无需改动。

### 五、删掉了曾被我建议删除的方案

我此前建议"删掉 `detectIntent` 或降级为可选信号"。**实测推翻了它**:

| 方案 | 正例召回 | 反例误伤 | 已知误报 | 真实命中 |
| --- | --- | --- | --- | --- |
| 现状 | 7/8 | 0/8 | 1/2 | 11/63 |
| 删除意图通道 | 6/8 | 0/8 | 0/2 | 7/63 |
| 本方案 (分层+同分句) | **8/8** | **0/8** | **0/2** | 8/61 |

删掉会**损失真实召回**; 正确做法是修判定精度。此外意图通道是唯一能在
"项目没有任何绑定/常驻内容"时触发注入的路径, 删掉会留下覆盖空洞。

## Alternatives considered

**删掉 `detectIntent`, 只留 always-on 与 drift 两条通道。**
实测正例召回 7/8 → 6/8, 并损失无绑定项目的唯一触发路径。否掉。

**降级为"可选信号" (只记录不参与决策)。**
等于删掉但不减代码, 且丢掉正例召回。否掉。

**把裸词表整表删除。**
正例 6/8 (丢掉"这个项目的约定是什么"), 而分层方案是 8/8。否掉。

**只按"整段同现"加门槛 (不做同分句)。**
实测长文本误报仍然存在 ("规范"与"如何"分处两句)。同分句才根治。否掉。

**提高 `minConfidence` 而不改置信度公式。**
旧刻度下所有命中都是 0.34, 抬到 0.40 直接让真实命中从 11 → 0 (悬崖), 无法调优。否掉。

**改用语义/模型判断意图。**
方向正确但成本与延迟不可接受 (触发层在每轮 pre-step 的同步路径上, 且当前
`memory_*` 工具调用实测为 0/7440, 先解决"有没有信号"比"信号多准"更紧要)。记为后续方向。

## Consequences

换来的: 真实语料命中率 17.5% → 13.1% (而且留下的比删掉的更准);
正例召回 7/8 → **8/8**; 两处真实长文本误报全部消除;
置信度第一次携带信息 (0.50/0.75 可区分), `minConfidence` 第一次真的能拦;
`policy.ts` 回到 284 行。

付出的: `TriggerIntent` 多一个字段; 判定多一次分句; 新文件 `intents.ts`。

诚实边界:
- **同分句只是缓解, 不是解决**。"同现 != 相关"在更长的文本里仍可能被绕过
  (例如同一分句里既列举规格又问别的事)。真正的解法是语义判定, 见 Alternatives 最后一条。
- 语料是**本项目自己的会话** (61 条), 且"正例/反例"由我人工标注, 存在标注偏差。
- 仍有 2 条长消息会命中 (如"调研一下这个项目…重点关注两个问题，如何开始训练")——
  它确实含疑问句且句内有话题词, 单靠词+句形无法区分"调研任务"与"问约定"。
- 阈值 0.5 与分句策略都是保守取值, 尚无线上真实反馈数据校准。

## Testing

- `tests/s1/trigger-policy.test.ts` 新增三组:
  - 话题词必须与提问形状同现: 陈述句里的裸词不算 (含真实误报原文), 同词进问句才算;
  - 话题词与提问形状必须**同分句** (分处两句不算) —— 长文本误报的回归锁;
  - 置信度不再钉死在下限: 1 条 = 0.50, 2 条更高 (断言单调而非具体数字), 上限 ≤ 1;
  - "'之前…过…吗' 这类口语回忆形状不再漏掉"。
- 既有 17 条意图/触发测试全部保持通过 (对外 API 与阈值语义未被破坏)。
- 全量: 641 tests / 91 files 通过; lint + 结构 (79 源文件) + 文档门禁通过。
